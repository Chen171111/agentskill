## 20 条方法论铁律（本项目踩出来的）

1. **先体检数据地基，再谈策略** —— ETF 线 4 处未复权拆分污染了全部回测；
   个股线因此补做了完整体检（`diag_stock_data.py`）。**地基错了，上面所有数字都不可信。**
2. **基准必须可投资** —— 用不可投资的等权全池做基准会否定一个好策略
3. **网格太稀疏会把中间点误判为峰值** —— 3 个点像尖峰，补邻域后发现是单调
4. **任何参数改动都必须过样本内外** —— `min_amount` 的改善就是被这一步否决的
5. **引擎里任何「跳过」分支都必须计数上报** —— `topk*2` 守卫静默跳过调仓，
   凭空造出「700 之后 alpha 转负」的假断崖（`docs/落地路径与资金门槛.md` §12）。
   曲线出现断崖时，**先怀疑引擎，别当成 alpha 衰减。**
6. **渐进式偏差必须用「重建数据」测，不能打补丁式截断** ——
   涨跌停判据只抓到 15,975 行（0.177%），据此的截断对照测出影响 −0.05pp；
   用不复权价重建后真实影响 **−0.89pp**，**低估约 10 倍**。
   **判据的覆盖范围要先想清楚，别把"判据没抓到"当成"不存在"。**
7. **外部数据的两个「假故障」**（2026-09-16 踩）：
   ① **主键格式不对齐会伪装成"数据源没覆盖"** —— 东财返回 6 位代码（`600000`），
   本项目日线带前缀（`SH600000`），首版没映射，覆盖率直接显示 **0/5,570（0.00%）**；
   加 `code_full` 后 99.98%。**看到 0% 命中，先查主键，别急着换数据源。**
   ② **别用「日期序列切片」重建调仓日** —— Brinson 归因里写 `dates[::hold]`
   （锚定全区间第一天）去过滤样本外的选股计划（锚定 2023 第一天），
   **两个相位不相交** → 样本外归因静默算不出来（当时只输出了全区间与样本内）。
   **调仓日必须从计划对象自己取。**
   ③ **执行环境的 `sys.path` 差异会伪装成「依赖缺失」**（2026-09-16 踩，第 3 类假故障）：
   我在沙箱里探测 `import akshare` 失败（`E://Python` / `E://Python32` / 托管 venv 全失败），
   据此写下「akshare 三个环境全缺 → 行情不会自动更新」并写进运行手册。
   **实际是错的** —— akshare 1.18.94 装在 `E://Python`（3.14）的**用户 site-packages**
   （`AppData\Roaming\Python\Python314\site-packages`，41 个包），
   当天 14:50 的计划任务**成功刷新了 11 只**。
   错因：**WorkBuddy 沙箱注入了 `...\cli\vendor\shim` 到 `sys.path`，
   而用户 site-packages 目录没进 `sys.path`** → `import` 失败。
   → **`import` 失败时先打印 `sys.path` 对照，别急着断言"依赖缺失/数据源不可用"。**
   沙箱里要复现真实行为，用 `PYTHONPATH=<用户站点目录>` 显式补上。
   **（与①②同源：都是"我把自己的观测环境当成了真实环境"。）**
8. **参数没生效 ≠ 测过了；「跑过」不等于「测过」。**（2026-09-16 踩）
   `hyst`（四进三出）的滞回阈值在默认 `entry=4%` 下**从未约束住任何东西** ——
   与朴素 `topn` **24 行（12 对）逐行相同、差 0.0**（2026-09-18 用 correct 口径复核一致），
   却被当成"测过了"记在文档里。
   → **任何带阈值的构造，交付前必须证明阈值真的 binding。**
   ⚠️ 而「是否生效」的判据**不能用代理变量**：第一版用「平均持仓 < N」判定，
   但 `entry=8/exit=4` 在样本外平均持仓仍是 **19.98 ≈ N** 而结果确实不同
   （`keep` 把已持有股票留在候选集里，挤掉了别的）→ 误判成"没生效"。
   **正确判据：结果与基线不同（掩码不同）。**
9. **复合机制必须拆开做对照 —— 而且对照结论本身也会随口径翻。**（2026-09-16 踩 / 09-18 复验）

10. **正交 ≠ 有增量；秩相关只能证明「不冗余」。**（2026-09-16 踩）

11. **单点推荐不算推荐；补完邻域才能定稿 —— 而且邻域经常推翻单点。**（2026-09-16 踩 / 09-18 复验）

12. **两个改进各自有效、叠加却无效时，先查「暴露维度」而不是「选股重叠」。**（2026-09-16 踩）
    直觉会告诉你"它们选了同一批股票"，**实测是错的**：
    `hyst 8/4` 与「行业内百分位」的选股重叠（Jaccard）只有 **0.27**（correct 口径三段均值 0.269/0.252/0.288）
    —— 选的是**两批完全不同的股票**。
    真正的抵消发生在**暴露维度**上（下列为 correct 口径样本外）：
    - `indpct` 的收益来源 = **降低行业暴露**（行业 HHI 0.111→**0.050**、行业数 12.1→**20.0**）
    - `hyst` **完全不改善行业暴露**（HHI **0.119**、行业数 12.0，与 `topn` 的 0.111/12.1 几乎一样）——
      它的 8% 高门槛天然偏向高股息行业，**把 `indpct` 刚建立的行业分散又吃掉一部分**
      （叠加后 HHI 0.070、行业数 16.6）→ **方向相反 → 必然抵消**

    （本次自造 `行业dy暴露 = Σ 行业权重 × 行业池内平均dy`），
    **方向相同 = 重叠，方向相反 = 抵消**。别只看选股名单。

    `min_dy` 在 **0.5% / 2.0% / 3.0% / 4.0% / 5.0%** 五个门槛下重叠度**逐位完全相同**（0.310）
    → 这些门槛值**全都不 binding**；**6.0% 才开始松动**（0.309）、**8.0% 才真正 binding**（0.256）
    （合格池前 20 名的 dy 中位本来就 7.55%/6.86%/8.04%）。**这是第 4 个实例。**

18. **批量改文档/代码时，别把参数追加到续行符 `\` 之后。**（2026-09-17 踩）

19. **改动引擎/口径前先建"同口径回归对照" —— 否则分不清是改动坏了还是口径变了。**（2026-09-17 踩）

    这个 8.8pp 的摆幅必须先归因才能下结论。做法：**同一份数据、同 `legacy` 口径，
    用新旧引擎各跑一遍**，得 Δ ∈ **[−0.137, −0.071]**，而预测的纯成本效应是
    `−0.0004 × 换手` ∈ [−0.122, −0.105]，**残差最大仅 0.034pp**
    → 引擎改动量级 = 成本修正，**没有结构性破坏**；那个摆幅来自**送转口径**。
    → 纪律：**口径变更 + 引擎变更同时发生时，必须用"锁定其中一个"的对照把责任分开。**
      顺带一条：以后写「复现 legacy 数字」要写成「**近似一致（差 ≈0.12pp = 成本修正）**」，
      **不能再写"逐位一致"**。

20. **"自优化"不能是"更快地调参" —— 评估可以自动，生效必须人工。**（2026-09-18 沉淀）
    本项目已证伪 5 条"自优化"路线（参数网格再搜 / 短线追强势股 / `dy` 入多因子 /
    `hyst` 阈值 / 压缩持仓），共同点是**都在同一份历史数据上继续搜**；
    而 `N` 与 `hold` 本身是**噪声参数**（波动 3~4pp）→ 再搜只是把噪音拟合得更漂亮。
    → 正确的工程形态是 **`tools/eval_candidate.py`：自动筛掉"无增量候选"**（收敛），
      而不是自动搜索"最优参数"（发散）。
    → 三层目标分级：**L1 监控（每日，只产状态/告警）／L2 数据（每日）／L3 模型（月度季度＋前向验证）**。
      **红线：每日闭环不得修改已定稿规则。**
    → **"每日学习" ≠ 每天重训模型**：60 日标签下每天新增有效样本只有 **1/60**，
      每天重训＝用几乎相同的数据反复拟合。每日只做：补数据 + 增量特征 + **标签回填** + 监控。
    → 配套：`tools/monitor_factors.py`（失效当天可见）、`tools/walk_forward.py`（DSR/PBO 校正多重检验）、
      `docs/需求规格_自优化闭环模块.md`（接口与判据定死）。
    → **越界先降级（降仓/暂停），不先找新参数。**
