## 11 条方法论铁律（本项目踩出来的）

1. **先体检数据地基，再谈策略** —— ETF 线 4 处未复权拆分污染了全部回测
   （`diag_price_anomalies.py`）。**地基错了，上面所有数字都不可信。**
2. **基准必须可投资** —— 用不可投资的等权全池做基准会否定一个好策略
3. **网格太稀疏会把中间点误判为峰值** —— 3 个点像尖峰，补邻域后发现是单调
4. **任何参数改动都必须过样本内外** —— `min_amount` 的改善就是被这一步否决的
5. **引擎里任何「跳过」分支都必须计数上报** —— `topk*2` 守卫静默跳过调仓，
   凭空造出「700 之后 alpha 转负」的假断崖。
   曲线出现断崖时，**先怀疑引擎，别当成 alpha 衰减。**
6. **渐进式偏差必须用「重建数据」测，不能打补丁式截断** ——
   涨跌停判据只抓到 15,975 行（0.177%），据此的截断对照测出影响 −0.05pp；
   用不复权价重建后真实影响 **−0.89pp**，**低估约 10 倍**。
   **判据的覆盖范围要先想清楚，别把"判据没抓到"当成"不存在"。**
7. **外部数据的三个「假故障」**（2026-09-16 踩）：
   ① **主键格式不对齐会伪装成"数据源没覆盖"** —— 东财返回 6 位代码（`600000`），
   本项目日线带前缀（`SH600000`），首版没映射，覆盖率直接显示 **0/5,570（0.00%）**；
   加 `code_full` 后 99.98%。**看到 0% 命中，先查主键，别急着换数据源。**
   ② **别用「日期序列切片」重建调仓日** —— Brinson 归因里写 `dates[::hold]`
   （锚定全区间第一天）去过滤样本外的选股计划（锚定 2023 第一天），
   **两个相位不相交** → 样本外归因静默算不出来（当时只输出了全区间与样本内）。
   **调仓日必须从计划对象自己取。**
   ③ **执行环境的 `sys.path` 差异会伪装成「依赖缺失」**（2026-09-16 踩，第 3 类假故障）：
   我在沙箱里探测 `import akshare` 失败（`E://Python` / `E://Python32` / 托管 venv 全失败），
   据此写下「akshare 三个环境全缺 → 行情不会自动更新」并写进运行手册。
   **实际是错的** —— akshare 1.18.94 装在 `E://Python`（3.14）的**用户 site-packages**
   （`AppData\Roaming\Python\Python314\site-packages`，41 个包），
   当天 14:50 的计划任务**成功刷新了 11 只**。
   错因：**WorkBuddy 沙箱注入了 `...\cli\vendor\shim` 到 `sys.path`，
   而用户 site-packages 目录没进 `sys.path`** → `import` 失败。
   → **`import` 失败时先打印 `sys.path` 对照，别急着断言"依赖缺失/数据源不可用"。**
   沙箱里要复现真实行为，用 `PYTHONPATH=<用户站点目录>` 显式补上。
   **（与①②同源：都是"我把自己的观测环境当成了真实环境"。）**
8. **一次性打补丁治不了「上游会覆盖」的问题 —— 修复必须放在读取路径上。**（2026-09-16 踩）
   09-13 修好的 4 处 ETF 份额折算，**09-16 被每日刷新静默回退** ——
   `DataStore.refresh()` 会用 akshare 的**原始未复权全量历史**覆盖 `data/stocks/*.csv`。
   **没有任何机制发现这件事**，靠人偶然翻目录才查到；实测代价 **0.98pp/年**
   （`tools/cmp_split_impact.py`：同一文件、只切换是否复权 → 2.35% vs 3.33%）。
   → **修在「读取时」（`dataprovider/adjust.py` + `DataStore.read()`）才是根治**：
   无论文件被覆盖多少次，策略读到的永远连续；而且**幂等**。
   **凡是有「上游会重写这份数据」的场合，补丁都不能只打在数据上。**
   配套：`tools/refresh_data.py` 现在挂了体检（复权后仍有超阈跳变 → 写 `state/DATA_ALERT.txt`），

     见 `docs/参考_A股ETF涨跌幅限制.md` §六；复盘详见 `docs/ETF线_复权阈值缺陷.md`。
10. **批量改文档/代码时，别把参数追加到续行符 `\` 之后。**（2026-09-17 踩）
    为批量给多行命令补参数，按「第一次匹配的行」追加 → **续行链被打断**，
    命令既跑不了、审计也认不出它。**参数必须追加到逻辑命令的"最后一行"。**
    同一批操作还踩了第二个坑：Python `open(p, "w")` 在 Windows 下会把 `\n` 翻成 `\r\n`，
    而仓库里是 LF → **没打算改的文件全部变成"已修改"**。
    → 纪律：**批量写文件用 `open(p, "wb")`（或 `newline=""`）**；
      改完立刻 `git status` 复盘，确认"改动的文件 = 打算改的文件"。
      收尾时 `git checkout --` 还原非目标文件，别把换行符噪音混进提交。
11. **会下单的脚本必须拒绝未知参数 —— "我只是想看看用法"不能变成一次真实下单尝试。**（2026-09-19 踩）
    `tools/daily_job.py` 内部执行 `main.py simulate --ths`（**真实交易链路**），
    但它原本对参数**不做任何检查** → `daily_job.py --help` **不会打印用法**，
    而是**照常执行整条链路**。
    实际后果（2026-09-19 23:57）：用 `--help` 试探 → 触发一次真实运行 →
    失败在 broker 连接阶段（**未产生任何交易**，`trading.db` 未动），
    但覆盖了 `state/last_run.json`、写出 `state/ALERT.txt`
    → `check_alerts.py` 误报「自动交易失败」。
    → 纪律：**任何会下单 / 写状态 / 发消息的脚本，都必须在最前面做参数白名单校验**
      （见 `daily_job.py` 的 `_ALLOWED_ARGS`），未知参数**非零退出、拒绝执行**；
      而且守卫必须写在**构造下单命令之前**（`selftest` 已断言这个顺序）。
    → 配套：**想知道用法就读 docstring，不要执行**；调试 / 额外重跑一律加 `--manual`
      （写独立状态文件，不污染计划运行的健康记录）。
