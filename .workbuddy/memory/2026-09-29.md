## 15:00 Order 语义核对完成（4 项待办的第 1 项）

### 结论：语义「自洽」，并修掉 3 处台账保真缺陷

2026-09-13 提出的「`Order` 语义不一致」**已消解** —— 两条链路确实行为不同，
但 `UiaThsBroker` 是**正确**的那一侧：

| 环节 | 行为 | 判定 |
|---|---|---|
| `UiaThsBroker.submit()` | `status="submitted"` / `filled_qty=0` | ✅ 诚实反映「已报未成」 |
| `UiaThsBroker.sync_fill()` | 回读当日委托，`已成`→`filled` + 成交均价/量 | ✅ 与真实券商语义一致 |
| `execution.rebalance()` | 只对 `status=="filled"` 调 `apply_fill` | ✅ 真实路径不误触发 |
| `runner.run_once()` | 下单 → reconcile → 逐笔 sync_fill → 落库 | ✅ 顺序正确 |
| 旧 `ThsBroker.submit()` | **无条件**置 `filled` + `filled_qty=order.qty` | ⚠️ 把「已报」当「已成」，已弃用、零调用点 |

**修掉 3 处缺陷**：
1. **`sync_fill` 不校验方向（真 bug）** —— 当日委托同代码可有多行且方向相反
   （部分成交补单 / 同日重跑 / 人工委托撞车），旧实现命中即返回第一行 →
   买单被写进卖单的成交价与成交量。→ 新增纯函数 `ths_parse.match_order_row()`
   （`code+方向+数量` → `code+方向` → 仅当全部候选无方向才兜底第一行；
   **只要存在方向明确且相反的行就返回 None**，宁可台账停 submitted 也不用错行）。
   回归 `test_ths_parse.check_order_row_matches_side`。
2. **`sync_fill` 静默吞异常** → 改为打印告警后 return（runner 层告警原先**永远收不到**）。
3. **`submit()` 用委托价冒充成交价** → 置 `None`（展示层 `filled_price or price` 兜底）。

### 重构：弃用「关键词起点」，改「行尾市场词锚定」

`_tail_six()`：委托表行尾 6 列在**全部 5 帧**里稳定读出，且紧邻「交易市场」列。
以市场词（`上海A股|深圳A股|北京A股`）为锚，取其前的数字序列，从后往前取 6 个；
合同编号额外要求 **≥9 位整数**以排除「当日成交」表（其尾部编号仅 7 位）；
锚不上 → 返回 None → 退回关键词路径（`parse_trades` 同时服务两种表）。

配套：
- **status 数量兜底** —— 文本列读坏时用「成交数量 ≥ 委托数量」判已成，否则
  `sync_fill` 的 `status` 永远停在 submitted；「已撤/废单」优先级提最前
- **name 抽取** —— 不再用「买入|卖出」分割（读不出时把状态与数字整段吞进来，
  实测 `'2S500ETF32k全'`），改「按 ≥2 连续空白切名称列 → 剔操作/状态词」
- **`fetch_today_orders` 选帧** —— `len(cur) > len(best)` → `_order_frame_score()`。
  只有 1 笔委托时所有帧行数相等 → 旧实现**永远保留第一帧**，而第一帧恰是
  名称带噪串（`#R@S500ETF 32h`）的那帧。**行数相同 ≠ 信息等价。**
- **`sync_fill(order, rows=None)`** —— 可传入已抓的 rows，省掉一次 35 s 连拍，
  且保证同一次校验用同一份数据（3 次连拍本身可能拿到不同帧）

### `match_order_row` 方向匹配的真实地位（实测更正）
