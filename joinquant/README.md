## 二、怎么跑

### 2.1 定稿版

1. 聚宽 → 策略研究 / 回测 → 新建策略：
   - **策略类型选「股票策略」，不要选「多因子策略」**。
     多因子模板 = 聚宽自带因子框架（`jqfactor` 取因子 + 标准化 + 行业中性化 + 定期调仓），
     而**聚宽因子库没有 TTM 股息率因子**、它的中性化口径也与本项目不同
     → 选了它只会把骨架整段删掉，白选。
     「股票策略」给的标准 `initialize` + `run_daily` + 手动下单骨架，正好与本文件结构一致。
   - 建好后**把模板代码全选删除**，再整段贴 `jq_dividend.py`
     （⚠️ 不要让两套 `initialize` 并存：重名函数后者覆盖前者，出问题极难查）
2. 回测设置（**必须对齐**，否则与本地不可比）：
   | 项 | 值 |
   |---|---|
   | 起始 | **2019-01-02** |
   | 结束 | **2026-09-11** |
   | 频率 | **日线** |
   | 初始资金 | **100000** |
   | 基准 | 代码里已 `set_benchmark('000852.XSHG')`（中证1000） |

3. 跑完记下 年化 / 夏普 / 最大回撤 / 超额

### 2.2 裸版对照（**别跳过**）

把 `FORM = 'indpct'` 改成 `FORM = 'naked'`，再跑一次。

裸版 = **只按股息率排序取前 20**（`min_dy=0.5%` 保留，去掉 `≤10%` 上限和 `≥2次` 过滤，
不做行业中性）。它对应本地那条 **全区间 6.82%、还跑输中证1000（−0.23pp）** 的曲线。

**为什么必须跑**：定稿的全区间 18.94% 里，`≤10%` 上限一个人贡献 **+8.64pp**、
行业内排序贡献 **+2.86pp**，而这两条规则都是**看过全区间结果才挑的**（事后选择偏差）。
定稿数字与裸版数字的差，就是「事后挑选」在聚宽数据上的量级估计。

## 三、口径映射（已对聚宽官方文档核实，非猜测）

| 定稿要求 | 本地实现 | 聚宽实现 |
|---|---|---|
| 全 A 池（含退市） | `universe_all.csv`（生存者偏差已修正） | `get_all_securities(types=['stock'], date=选股日)` ← **带 date = point-in-time** |
| 剔 ST | `universe.is_st` | `get_extras('is_st', ...)`（含 `*ST` / 退市整理期） |
| 上市 ≥120 交易日 | `listed = cumcount+1` | `get_trade_days` 索引差（等价，见 §四 注） |
| 20 日均成交额 ≥3000 万 | `amt_ma20`（含当日的 20 日均值） | `get_price(fields=['money'], count=20)` 按 code 取均值 |
| 收盘价 ≥2 元 | `close`（**总收益指数价**） | `get_price(fq='none', fields=['close'])`（**不复权真实价**，见 §四 差异 2） |
| 非停牌 | `volume <= 0` | `get_price(fields=['paused'])` |
| `dy_ttm` | 东财 `PRETAX_BONUS_RMB` ÷ 10 ÷ `bars_bfq.close` | `STK_XR_XD.bonus_ratio_rmb` ÷ 10 ÷ `fq='none'` 收盘价 |
| 送转调整 | `BONUS_IT_RATIO`（送转合计） | `dividend_ratio`（送股）+ `transfer_ratio`（转增） |
| 分红持续性 `n_div3` | 近 1095 天 `EX_DIVIDEND_DATE` 现金分红次数 | 近 1095 天 `a_xr_date` 且 `bonus_ratio_rmb > 0` 的次数 |
| 一级行业 | 东财 `EM2016` 一级（28 个） | `get_industry(..., date=)` 的 `sw_l1`（申万一级，约 31 个；`SECTOR` 可切 `jq_l1`/`zjw`） |
| 行业内 `dy` 百分位 | `dy.groupby(ind).rank(pct=True)` | 同（同一句 pandas） |
| 佣金万 5 + 最低 5 元 | `NOMINAL_FEE=0.0005` / `MIN_COMMISSION=5` | `OrderCost(open_commission=0.0005, close_commission=0.0005, min_commission=5, type='stock')` |
| 卖出印花税 0.1% | `STAMP=0.001` | `close_tax=0.001` |
| 滑点单边 0.05% | `SLIP=0.0005` | `set_slippage(PriceRelatedSlippage(0.001))` = 双边价差 0.1% → **单边 0.05%** |
| T+1 开盘执行 | 引擎在 `t+1` 开盘撮合 | `run_daily(rebalance, time='09:30')` + 用 `t-1`（`previous_date`）数据选股 → 聚宽在开盘时刻按**开盘价**撮合 |
| 买入遇涨停开盘 | 跳过，资金不补 | **交给聚宽撮合**：买单在涨停价上无法成交，未成交订单当日撤销（等价） |
| 持有期内不再平衡 | 掩码只在调仓日生效 | 只在调仓日调用 `order_target_value`，其余日子函数直接 return |

## 四、会和本地**分叉**的地方（别拿聚宽的数字核对本地数字）

| # | 差异 | 说明 |
|---|---|---|
| 1 | **数据源不同** | 分红明细、复权因子、退市处理都不同 → 逐股 `dy` 会有差异 |
| 2 | **`min_price` 的分母口径不同** | 本地门槛卡在**总收益指数价**上（含分红回放，历史区间比真实价低约 14%），聚宽卡在**不复权真实价**上。`2 元` 这条边界附近的股票入选名单会不同 |
| 3 | **行业分类不同** | 东财 `EM2016` 一级（28 类）≠ 申万一级（约 31 类）。**换分类 = 换中性化基准 = 换选股结果** |
| 4 | **⚠️ 10 万 + 100 股整手** | 10万 ÷ 20 = **5000 元/笔** → **股价 > 50 元的股票买不进 1 手**，会被跳过。本地引擎**不建模整手**。→ 这是与本地最主要的结构性分叉，每次调仓日志里会打印被跳过的股票 |
| 5 | **`n_div3` 的窗口** | 都用「近 1095 **日历**天」，一致；但本地 `d3y` 是按交易日数组平移，边界日可能差 1~2 天 |
| 6 | **时间边界** | `ANCHOR_DATE` 必须落在回测区间内；若改了回测区间，**必须同步改** `ANCHOR_DATE` / `TRADE_END`，否则调仓相位错位 |
| 7 | 上市时长口径 | 本地 `listed` = 「数据集内 K 线根数」（数据集从 2018-01-02 起）；聚宽用真实上市日期。**两者在 `backtest 起点 2019-01-02` 下等价**（2018 年前上市的老股在两边都 ≥120），但若把回测起点提前就不等价了 |

**结论：看**方向与量级**，不要看小数点。**

## 六、本次移植**发现的两个问题**（都还没改研究模型，等主人拍板）

### 6.1 ⚠️ 本地 `dps_ttm` 的送转调整**方向是反的**（已用决定性判据确证）

`tools/test_dividend_factor.py` 里：

```python
adj[i] = Π_{j>i} (1 + r_j)          # j 遍历**全部分红历史**，不设上界，而且是**乘**
```

两个毛病：
1. **时间上没上界** —— `t` 之后才发生的送转，也被用来放大 `t` 之前的历史 DPS
2. **方向是乘**（应该是**除**）

**判据（决定性）**：送转是**价值中性**的 —— 1 股变 2 股，股价腰斩，每股分红摊薄一半
→ **在纯送转的除权日前后，股息率不应该跳变**。

`joinquant/_verify_core.py` 第二部分的实测（37 个「纯送转 + 前 1 年内有现金分红」事件，
配 `bars_bfq` 不复权真实价）：

| 口径 | 公式 | dy 在送转日的中位比值 | 偏离 1 | 偏离 (1+r) |
|---|---|---|---|---|
| **L 现行**（本地 & 本文件夹默认） | `Σ D_i · Π_{k>i,全部}(1+r_k)` | **1.446** | 0.446 | **0.031** ← 精确贴合 (1+r)，即跳变了 |
| W 只去未来送转（仍乘） | `Σ D_i · Π_{i<k≤t}(1+r_k)` | 2.060 | 1.060 | 0.639 ← 更糟 |
| **C 正确口径** | `Σ D_i / Π_{i≤k≤t}(1+r_k)` | **1.008** | **0.022** | 0.401 ← **连续** ✓ |

逐个样本也对得上：`SZ300442` 20230524、`1+r=1.80` → 比值 L **1.83**、C **1.01**。

**C 的推导**：在 `i` 的除权日持有 1 股，到 `t` 时变成 `Π_{i≤k≤t}(1+r_k)` 股；
那笔现金摊到「当前每股」上要**除**这个因子，而不是乘。

**处理**：
- `jq_dividend.py` 加了开关 `ADJ_MODE`，**默认 `'legacy'`（复刻本地，保证两边可比）**，
  改一行 `'correct'` 就能在聚宽上跑修正口径 → 这是**成本最低的验证途径**
- ⚠️ **没有**改本地 `tools/test_dividend_factor.py` —— 修它会牵动**全部历史结论**
  （年化、样本内外、`N`/`hold` 邻域、行业中性化的 Brattle、`hyst` 阈值检验……），
  属于独立的研究口径变更任务，**不在本次移植范围内**

### 6.2 文档 §2.5「候选池 < 20 → 剩余资金留现金」与实现不一致

本地引擎 `tools/backtest_stock.py` 的 `cond_col` 分支：

```python
wv = np.ones(len(sel)); wv = wv / wv.sum()      # 等权、满仓
```

→ 候选只有 12 只时，每只分 **1/12**，**不存在「剩余资金留现金」**。
`jq_dividend.py` **按实现走**（等权买满）。文档那句话应更正。

### 6.3 移植过程中**自己踩到并修掉**的 bug（留档）

`_yield_at()` 的 `correct` 分支第一版把 `P(t) = Π(1+r)` 写成了**全市场一起连乘**
（而非按 `code` 分组）→ 直接 `overflow encountered in reduce`。
**这就是为什么 §七 那个离线自检必须先跑** —— 它一眼就把这个错抓出来了。
