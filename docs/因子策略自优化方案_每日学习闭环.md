# 因子策略自优化方案：每日学习闭环

> 2026-09-18 ｜ 承接 `docs/个股线_收益归因与优化路径.md`（为什么调参没用）
> 本文回答：**短板在哪 / 每日学什么 / 学出来的东西怎么用 / 怎么证明没学坏**
> 前置结论（不重复论证）：**目标收益只能来自"新信息源"，不能来自"更快的调参"**

---

## 零、先把「自优化」的目标说死

**❌ 错误目标**：「每天用最新数据重新搜索最优参数，让回测收益更高」
→ 本项目已证伪 5 次。`N`/`hold` 是噪声参数（波动 3~4pp），每日搜索 = 每日拟合一次噪音。

**✅ 正确目标**（三层，按允许的"动作幅度"分级）：

| 层 | 目标 | 每日允许做吗 | 判据 |
|---|---|---|---|
| **L1 监控层** | 让"策略正在失效"**当天就被发现** | ✅ **每天** | 滚动 IC / 暴露漂移 / 候选池 / 拥挤度 越界即告警 |
| **L2 数据层** | 让模型每天吃到**完整、干净、对齐**的数据 | ✅ **每天** | 数据体检全过 + 特征覆盖率 ≥99% |
| **L3 模型层** | 让**新信息源**被持续、严格地检验并吸收 | ❌ **不能每天**（月度/季度 + 前向验证） | 五闸门全过 + 影子期 ≥1 个调仓周期 |

> **红线**：**每日闭环不得修改已定稿的策略规则**。
> 每日只能（a）更新数据（b）产监控指标（c）**标记**候选失效；
> 任何规则/参数/因子的变更必须走 §五 的闸门 + 影子验证 + 人工确认。

## 一、当前因子策略的短板（逐条对数字）

### 1. 信息源太单一（**根因**）

| 现状 | 问题 |
|---|---|
| 有效信息 = **股息率 + 8 个价格量类因子** | 全部来自"行情 + 分红"两类数据，**同源同族** |
| 股息率 60 日 IC **0.0553**，低于 `vol20` 的 **0.0935** | 它甚至不是最强因子，赚钱靠**低换手**（2.64x/年） |
| `dy_ttm` 与 8 因子秩相关 7/8 个 \|ρ\|<0.1 | 看着"正交"，但样本外增量 **−1.76pp** → **正交 ≠ 有增量** |
| **8/8 因子全是价格衍生**（反转/波动/流动性） | 没有一条来自**基本面、资金面、事件面** |

→ **短板 #1：所有因子共享同一份信息源，边际信息早就被榨干。** 这是 IC 上不去的根本原因。

### 2. 无风险模型（**次因，且是最便宜的改进**）

现状：选股靠"行业内股息率百分位"，**没有市值/波动/流动性中性化**。

| 后果 | 证据 |
|---|---|
| 收益里混着**风格暴露** | 本项目已量化：8 因子约 **11% 的收益来自风格暴露**（`sweep_neutral.py`） |
| 行业暴露**漂移无监控** | `hyst`（8% 门槛）天然偏向高股息行业，把 `indpct` 刚建立的分散吃掉 → 两者叠加**互相抵消（−0.64pp）** |
| 组合 HHI 只在报告里事后看 | 没有**逐日**监控 |

→ **短板 #2：没有风险模型，所以"赚的是 alpha 还是 beta"在事前无法区分。**

### 3. 标签与验证存在**结构性问题**

| 问题 | 具体 |
|---|---|
| **重叠窗口** | 60 日标签 + 60 日调仓 → 相邻样本的标签**高度重叠**，有效样本数远小于名义样本数（IC 的 t 值被高估） |
| **无 purged/embargo 切分** | 现有样本内外是**按日历硬切**（2019-2022 / 2023-2026），训练段与测试段边界仍有标签重叠 |
| **多重检验未校正** | 已搜过 `N`×`hold`=28 个点、`hyst` 邻域 24 个点、6 个邻域… **没有做 deflated Sharpe / PBO 校正** |
| **样本外只有 15 期** | 单期（2026-03-27）占一半拖累 → 置信区间极宽 |

→ **短板 #3：验证框架不足以支撑"又找到一个小 alpha"这种结论。**

### 4. 无自适应与降级机制

| 现状 | 风险 |
|---|---|
| 参数定死（`N=20`/`hold=60`） | 若信号衰减（IC 从 0.055 掉到 0.02），**没有任何机制会告诉你** |
| 分红 5/8 年为正（2021/2024/2025 为负） | **整年失效**——但模型照买不误 |
| 只有"纸面跟踪"这一层前向验证 | 前向与回测的偏离没有**逐日**度量 |
| 风控只有对账/新鲜度/熔断（ETF 线） | 个股线**无风控** |

→ **短板 #4：策略没有"体温计"，也没用"退烧药"。**

### 5. 工程侧的短板（不影响结论，影响迭代速度）

- 数据只到 **20260915**（落后 2 个自然日，无自动补）；分红/行业**手动抓**
- 长任务**无断点续跑**（刚修，`tools/progress.py` + `run_reruns.py`）
- 无自动化候选评估（五闸门靠人手跑）
- 行业分类是**当前快照**，非 point-in-time（轻微前视）

| 业绩预告 / 快报 | 🟡 同上（需确认接口） | 事件型因子 |

> → **每接一个新源，必须先写一条 `selftest.py` 检查**（覆盖率 + 主键对齐 + 量级合理性）。

## 三、每日学习闭环的架构（谁在什么时候做什么）

```
T 日 15:00 收盘
   │
   ├─① 数据层（每日）      refresh_data → 体检 → 增量 append_stock_bars
   │                      → 周度：分红/行业/指数
   ├─② 特征层（每日）      重算当日横截面特征（8 因子 + dy + 风险特征）
   ├─③ 标签层（每日）      回填 T-60 日的真实前向收益（标签随数据推进自动"到期"）
   ├─④ 监控层（每日）★    滚动 IC / ICIR / 暴露漂移 / 候选池 / 拥挤度 / 前向偏离
   │                      → 任一越界即写 state/LEARN_ALERT.txt
   ├─⑤ 决策层（月度/季度）  五闸门自动化评估 → 影子期 → 人工确认 → 才允许改规则
   └─⑥ 执行层（调仓日）    现有定稿规则（**每日闭环不介入**）
```

### 关键设计：**标签回填**是"每日学习"的正确形态

"每日学习"最容易做错的地方是**每天重训模型**。正确做法是：

- **每天只做两件小事**：① 追加今日特征 ② 把 60 个交易日前的样本**打上已实现的标签**
- 模型**不每天重训**，只在月度/季度重训，且必须过 walk-forward + 影子期

理由：60 日标签意味着**每天新增的有效样本只有 1/60**（重叠窗口），
每天重训 = 用几乎相同的数据反复拟合 → **纯粹的噪音放大**。

## 四、频率设计（**这是本方案的核心**）

| 频率 | 做什么 | 允许改变什么 | 不允许改变什么 |
|---|---|---|---|
| **每日** | 数据刷新 + 特征/标签增量 + 监控指标 | 只更新**状态与告警** | ❌ 任何策略规则、参数、因子权重 |
| **每周** | 分红/行业/指数增量；滚动 IC 周报；拥挤度 | 候选池标签、监控阈值 | ❌ 同上 |
| **每月** | 五闸门评估**已排队**的候选；purged walk-forward 重训 | 候选进入影子期的资格 | ❌ 直接改定稿参数 |
| **每季（调仓日）** | 影子 vs 实盘对比；规则是否切换的**决策点** | 经人工确认的规则切换 | ❌ 自动切换 |
| **每半年** | 全量回灌 + 结论复扫（`run_reruns` + `selftest`） | 结论口径（**需报备**） | — |

> **纪律**：**变更的"评估"可以自动化，"生效"必须人工确认。**
> 本项目已经因为"自动/静默变更"吃过三次大亏（`hyst` 静默退化、引擎静默跳过、份额折算被刷新回退）。

## 五、评估指标（分三层，全部要可执行）

### 5.1 策略层（判断"有没有变差"）

| 指标 | 阈值 / 用法 |
|---|---|
| 样本外年化（税后·10万真实） | 基准 7.45%；低于 **7.45 − 3pp = 4.45%** 即触发复核 |
| 相对中证1000 超额 | 基准 +3.42pp；跌破 **0** 即视为失效 |
| 滚动 12 个月 IC | 低于 **0.02** 连续 3 个月 → 告警（信号衰减） |
| 夏普 / 最大回撤 | 0.53 / −26.13%；回撤突破 **−30%** → 降仓 |
| **前向 vs 回测偏离** | \|前向年化 − 回测样本外\| > **5pp** → 暂停并归因 |

### 5.2 因子层（判断"因子还活着吗"）

| 指标 | 说明 |
|---|---|
| **RankIC / ICIR**（60 日） | 当前 RankIC 0.0553；**ICIR < 0.3** 视为不稳定 |
| 分年度 IC 为正的比例 | 当前 **5/8**；掉到 4/8 以下要警惕 |
| **分组单调性** | 十分位顶底差 **+3.50pp 且非单调**（最高是 D9 不是 D10）→ 已记录，持续监控 |
| **因子衰减速度** | IC(1日) / IC(20日) / IC(60日) 的比值 |
| **拥挤度** | 同因子在同类产品/指数成分中的暴露集中度 |
| **换手** | 当前 2.64x；上升 50% 以上要重算成本 |

### 5.3 组合层（判断"暴露有没有漂移"）

| 指标 | 基准 | 阈值 |
|---|---|---|
| 行业 HHI | indpct ≈ **0.050** | 抬升 >30% → 检查行业标签缺失 |
| 行业数 | indpct ≈ **20** | < 15 → 告警 |
| 市值中位数分位 | 待建立基线 | 偏离 >1 个十分位 → 告警 |
| 单行业权重上限 | 15% | 超过 → 记录 |
| 平均股息率 | 4~6% | < 3% → 市场高估信号 |

### 5.4 过拟合防线专用指标（**必须做，本项目从未做过**）

| 指标 | 作用 |
|---|---|
| **Deflated Sharpe Ratio (DSR)** | 校正"搜了多少个配置"对夏普的膨胀 |
| **PBO（Probability of Backtest Overfitting）** | 估计"样本内最优在样本外排名后 50%"的概率 |
| **purged + embargo 的 walk-forward** | 消除标签重叠导致的信息泄露 |
| **参数平台检验** | 邻域是否同向（**不通过 = 拒绝**） |

## 六、如何避免过拟合与策略失效（**防线的具体落法**）

| # | 防线 | 具体做法 | 本项目落点 |
|---|---|---|---|
| 1 | **信息不泄** | 任何特征只能用 `≤ T` 的数据；标签回填只到"已到期" | `require_adj_mode` 式的**严格化**；`verify_adj_pointintime.py` 的差异必须为 0 |
| 2 | **标签不重叠** | purged walk-forward + embargo（≥ 标签长度） | 新增 `tools/walk_forward.py` |
| 3 | **多重检验校正** | 报 DSR/PBO，而不是裸夏普 | 新增，写进报告模板 |
| 4 | **平台而非刀尖** | 邻域 ≥3 点同向 | 五闸门②（**已有传统**） |
| 5 | **锁箱（hold-out）** | 最后一段数据**只在定稿时用一次** | 建议把 **2026 年**设为锁箱 |
| 6 | **强制影子期** | 任何变更先跑 ≥1 个调仓周期的影子权重 | 复用 ETF 线的 `shadow_weights` |
| 7 | **变更最小化** | 每月只允许**一个小步**，且记录 diff | `state/learn/changelog.jsonl` |
| 8 | **可回滚** | 每次变更前快照参数与权重 | 现有 `state/` 快照机制 |
| 9 | **降级优先于优化** | 越界先**降仓/暂停**，而不是找新参数 | 退出条件（见下） |
| 10 | **单一来源 + 自检** | 口径/成本/判据只有一处实现 | `tools/costs.py` + `tools/selftest.py`（已有） |

**失效的判定与动作（先定，避免"再给它一次机会"）**：

| 触发 | 动作 |
|---|---|
| 滚动 12 个月 IC < 0.02 连续 3 个月 | 降低仓位至 1/2，停止新增资金 |
| 前向 vs 回测偏离 >5pp 且无解释 | **暂停该线**，重新归因 |
| 前向年化连续 4 期 < 中证1000 | 停止，不追加资金 |
| 因子拥挤度进入历史 90 分位 | 减仓，不新增 |

## 七、实现方向（模块清单，可逐项开工）

| 模块 | 文件 | 职责 | 复用 |
|---|---|---|---|
| **候选评估器** ★最高优先 | `tools/eval_candidate.py` | 输入一个候选 → 自动跑五闸门 → `PASS/FAIL + 证据表`；FAIL 自动追加"已证伪清单" | `backtest_*` / `costs.py` |
| **Walk-forward** | `tools/walk_forward.py` | purged + embargo 切分；输出 DSR / PBO | `test_industry_neutral` 的 `plan_selections` |
| **因子监控** ★ | `tools/monitor_factors.py` | 逐日/周度产滚动 IC、暴露、拥挤度、前向偏离 → `state/LEARN_ALERT.txt` | `selftest` 的告警模式 |
| **每日增量** | `tools/daily_learn.py` | ① 特征增量 ② **标签回填** ③ 监控调用；写 `state/learn/` | `progress.py`（增量落盘） |
| **影子权重** | 复用 `shadow_weights` 表 | 记录"若执行"的组合，只记录不下单 | ETF 线已有 |
| **数据周更** | `tools/weekly_data.py` | 分红/行业/指数增量 + 体检 | `fetch_*` / `append_stock_bars` |
| **编排** | `tools/run_reruns.py` 扩成通用步骤表 | 断点续跑 | 已有 |

**开工顺序（按"收益 ÷ 成本"）**：

1. **`eval_candidate.py`** —— 没有它，任何候选评估都是手工、易漏、不可复现
2. **`monitor_factors.py`** —— 让"策略正在失效"当天可见（当前完全不可见）
3. **`walk_forward.py` + DSR/PBO** —— 补上验证框架的硬缺口
4. **`daily_learn.py`** —— 把前三者串成日常
5. **风险模型中性化**（市值/波动/流动性）—— 预期是**最确定的一笔收益**（现约 11% 收益来自风格暴露）
6. 然后才是 §2.2 的新数据源（财务质量 → 资金流 → 事件）

## 八、预期收益与诚实的边界

| 项 | 预期 | 依据 |
|---|---|---|
| 风险模型中性化 | **最确定**（1~3pp 或至少降波动/回撤） | 已有证据：行业中性化让组合变好（+2.41pp） |
| `dy_fwd` 事件型 | 1~2pp（**若不成立则记为已证伪**） | 数据已在手、机制正交 |
| 财务质量类 | 1~3pp（不确定性高） | 需先过五闸门 |
| 监控/影子/失效检测 | **不增收益，但防大亏** | 本项目三次大坑都是"没人发现" |

**必须说清的边界**：
1. **~11% 是当前信号质量的天花板**（本项目已结论）。自优化方案的**主要价值是"不再变差"和"更早发现失效"**，
   而不是把 7.45% 变成 20%。
2. **每日学习改变不了"弱信号"的本质**。IC 0.055 的因子，信息论意义上榨不出更多。
3. **样本外只有 15 期** → 任何"提升"都必须在**前向数据**上复核，否则不算数。
4. **10 万资金的硬约束**：持仓数不能升（最低佣金惩罚），换手不能升（成本），
   所以"更快的迭代"必须服务于**更稳**，而不是**更频繁**。

## 九、一句话

**短板不是"因子不够多"，是**：① 所有因子同源同族（都来自价格+分红）② 没有风险模型（赚的是 alpha 还是 beta 事前分不清）
③ 验证框架不防多重检验与标签重叠 ④ 没有失效监控。

**"每日学习"的正确形态**：每天做**数据增量 + 标签回填 + 监控告警**（三件都不改规则），
把"学出来的东西"放进**月度/季度的五闸门 + 影子期 + 人工确认**通道。
**能自动化的只有"评估"，"生效"必须人工；越界先降级，不先找新参数。**
