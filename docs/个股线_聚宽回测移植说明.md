# 个股线（股息率策略）· 聚宽回测移植说明

> 2026-09-17 ｜ 从 `docs/个股线_股息率实盘方案.md`（定稿）抽出，供**移植到聚宽回测**使用
> ⚠️ **先读 §六「移植前必须知道的事」** —— 不读会白跑一轮

---

## 一、策略一句话

**全 A 池 → 双重过滤 → 行业内股息率百分位 → 前 20 只等权 → 持有 60 个交易日 → 每年 4 次。**

---

## 二、完整规则（可直接照做）

### 2.1 合格池

| 条件 | 阈值 |
|---|---|
| 市场 | 全 A |
| ST | 剔除 |
| 上市时长 | ≥ **120 个交易日** |
| 流动性 | 20 日均成交额 ≥ **3,000 万元** |
| 价格 | 收盘价 ≥ **2 元** |
| 停牌 | 剔除 |

### 2.2 过滤（两个，缺一不可）

| 条件 | 阈值 | 为什么 |
|---|---|---|
| 股息率上限 | `0.5% ≤ dy_ttm ≤ **10%**` | 十分位**非单调**：最高的是 D9（12.31%），D10 反而回落到 11.92% → **极高股息率是价值陷阱**（股价崩了 / 一次性特别分红） |
| 分红持续性 | 近 **3 个自然年**现金分红 **≥ 2 次** | 挡掉「今年分了明年不分」 |

### 2.3 排序（关键，别改成全市场排名）

**在【所属一级行业内】按 `dy_ttm` 算百分位（pct rank），取全局最高的 20 只。**

- 不是全市场排名取前 20 —— 那样会高度集中在银行/煤炭/钢铁
- 行业内百分位会**自然带来行业等权**：每个行业的百分位都是 [0,1] 上的均匀分布，取全局前 N → 各行业入选数大致相等（实测行业数 12 → 20，行业 HHI 0.107 → 0.050）
- Brinson 归因：**超额不是行业 beta** —— 行业配置超额 −1.69 / −0.03 / −4.54，选股超额 **+6.03 / +6.56 / +2.96**

### 2.4 权重与调仓

| 项 | 规则 |
|---|---|
| 持仓数 | **20 只** |
| 权重 | **等权，每只 5%** |
| 持有期 | **60 个交易日**（≈ 季度） |
| 调仓频率 | **每年 4 次** |
| **持有期内** | **不做任何操作** —— 不再平衡、不止损、不择时、不设移动止盈 |

> ⚠️ **「持有期内不再平衡」这条极其重要。** 60 天内权重自由漂移（涨的股票权重自然变大），只在下一个调仓日重建。
> 再平衡会把换手推上去，**直接吃掉「最低佣金 + 低税档」这两个优势**。

### 2.5 执行细节（回测里必须实现，否则数字会虚高）

| 情形 | 处置 |
|---|---|
| 调仓时机 | 调仓日**收盘后**选股 → **次日（T+1）开盘**执行 |
| 买入遇涨停开盘 | `open ≥ prev_close × 1.1`（创业板/科创板 **×1.2**）→ **该股跳过，资金不补** |
| 卖出遇跌停开盘 | 跳过，顺延到下一个可交易日出 |
| 停牌 | 无法交易 → 顺延到复牌 |
| 退市 | 按最后收盘价了结（本项目用 `writeoff_factor=1.0`，**偏乐观**，实际可能更低） |
| 候选池 < 20 | 有多少买多少，**剩余资金留现金**（不要用「次优」股票补满） |
| 候选池 < 5 | 视为**市场无高股息机会** → **空仓等待**，不硬凑 |

### 2.6 成本参数（必须显式设置）

| 项 | 值 |
|---|---|
| 佣金 | **万 5**（且**最低 5 元** —— 这条对小资金影响很大） |
| 卖出印花税 | 0.1% |
| 滑点 | 0.05% |

> 最低佣金是小资金的关键：20 只 × 5,000 元/笔时，实际费率被抬到 **0.1%**，比名义万5 高一倍。
> 本项目实测这一项让年化 **−0.28pp**（换手越低惩罚越小，这正是低频的价值）。

## 三、`dy_ttm` 的定义（最容易错的地方）

```
dy_ttm = 过去 12 个月【已除权】的每股现金分红总额
         ────────────────────────────────────────
              当日【不复权】真实收盘价
```

**两条硬约束：**

1. **分子用「已除权」口径**（`dy_ttm`），不用「未来 12 个月」的前瞻口径（`dy_fwd`）
   —— 不依赖公告时点，避免前视。
2. ⚠️ **分母必须是真实市价，不能用复权价或总收益指数。**
   本项目实测：分母口径错 14% → **结论错 19pp**。

## 四、聚宽实现要点

> ⚠️ **下面只给方向与核对要点，不给具体字段名** —— 聚宽的表名/字段名请以**官方数据字典**为准。
> 我在检索时拿到的第三方教程里，关键字段名作者自己都标注为「假设」，不可采信。

| 步骤 | 需要的数据 | 聚宽侧的可能来源（**需核对**） |
|---|---|---|
| 全 A 股票池 | 证券列表 + ST 标记 | `get_all_securities(['stock'])`、`get_extras` 的 ST 标记 |
| 上市时长 | 上市日期 | `get_security_info(code).start_date` |
| 20 日均成交额 | 日线成交额（元） | `get_price(..., fields=['money'])`，注意单位 |
| 收盘价 ≥ 2 元 | **不复权**收盘价 | `get_price(..., fq=None)` ← **`fq` 参数必须显式设成不复权** |
| 分红明细 | 每股现金分红 + 除权除息日 | 财务数据里的「分红送股」表（`finance.run_query`），或用因子库 |
| 股息率 | 可直接用现成因子 | `jqfactor.get_factor_values`，因子 code 用 `get_all_factors()` 查 |
| 一级行业 | 行业分类 | 聚宽自带行业分类（**口径与本项目不同，见 §六**） |

**建议的落地顺序**：
1. 先用聚宽**现成的股息率因子**跑一版，看量级对不对
2. 如果口径对不上（比如它给的是税前/最近一期而非 TTM），再自己用「分红明细 ÷ 不复权收盘价」重建
3. 两条都跑，**比对差异** —— 这个差异本身就是重要信息

## 五、本项目**已证伪**的变体（别浪费时间重试）

| 变体 | 结论 |
|---|---|
| **`hyst` 四进三出（entry 4% / exit 3%）** | ⚠️ **在默认参数下从未真正生效** —— 候选集恒包含 dy 前 N 名，与纯 top-N 选出同一批（24 个配置 8 项指标逐行完全相同，最大绝对差 = 0.0） |
| **`hyst 8/4`（调高阈值让它生效）** | 样本外与「行业内选股」**互相抵消**（4 个 hold 均值 **−0.64pp**），只在全区间/样本内加分。**定稿不采用** |

| 大盘择时（MA20 / 绝对动量 / RSRS / BIAS） | 已证伪 |
| 短线个股策略 | 已证伪 |
| 止损 / 移动止盈 | 已证伪（持有期内不做任何操作） |

## 六、⚠️ 移植前必须知道的事

### 6.1 这个形态有**大量事后选择**，聚宽会复现「乐观版」

把定稿拆成层层加码（全区间 2019-01-02 ~ 2026-09-11，N=20）：

| 层 | 年化 | 相对上一层 |
|---|---|---|
| **裸**（只有「按股息率排序取前 20」） | **6.82%** | — |
| ＋ `≤10%` 上限 | 15.46% | **+8.64pp** |
| ＋ `≥2次` 分红持续性 | 16.08% | +0.62pp |
| ＋ 行业内百分位排序（定稿） | **18.94%** | +2.86pp |

**「裸」版本全区间 6.82% 还跑输中证1000（−0.23pp）。**

而这两条关键规则（`≤10%` 上限、行业内排序）**都是看过全区间结果才挑的**。
→ **你在聚宽上大概率会跑出 18% 附近的「定稿」数字，别把它当预期。**
→ 诚实的预期应**显著低于** 10%，存在与基准打平甚至跑输的可能。

**建议你在聚宽上顺手做一件事**：把「裸」版本也跑一遍（只留排序，去掉两个过滤和行业内中性）。
这个对照比定稿那个数字有信息量得多。

### 6.2 移植后数字不会一致，原因有四

| 差异源 | 说明 |
|---|---|
| **数据源不同** | 本项目用 akshare / 腾讯 / 东财；聚宽用自己的库。分红明细、复权因子、退市处理都会有差 |
| **行业分类不同** | 本项目用东财 `EM2016` 一级行业；聚宽有自带的。**换分类 = 换中性化基准 = 换选股结果** |
| **股息率口径可能不同** | 聚宽的现成股息率字段可能是「最近一期」而非 TTM、可能是税前口径。务必核对 |
| **退市/停牌处理** | 本项目 `writeoff_factor=1.0` 偏乐观；聚宽的默认处理可能不同 |

**所以：不要拿聚宽的数字去核对本项目的数字**，两边对不上是正常的。要看的是**方向与量级**。

### 6.3 已知的局限（本项目的自述，你那边也会遇到）

1. **样本外只有 3.7 年 / 15 个调仓期** → 置信区间很宽。单期影响：2026-03-27 那期行业配置超额 **−9.62%**，占了一半拖累幅度。
2. **行业分类是「当前」标签，非 point-in-time** → 回测存在**轻微前视**。
3. **`N` 和 `hold` 都是噪声参数**（波动 3~4pp）→ **不要因为某期表现差就调参**。
   - `N` 邻域：N=10 → 11.96 / N=15 → **12.77** / N=20 → 10.38 / N=30 → 9.41 / N=50 → 11.34（样本外，行业内百分位）
   - `hold` 邻域：20 → 13.84 / 30 → 12.03 / 40 → 13.27 / 60 → **10.10**（样本外 10 万真实）
   - 定稿取 N=20 / hold=60 是**保守选择**，不是最优 —— 「选 hold=40 而不是 60」的唯一理由就是它样本外更高，**那正是过拟合**。
4. **回撤 −20.95%（样本外）不小**，20 只集中持仓有单票风险。
5. **红利税是平坦税率近似**（实际按持股期限差别化、FIFO 补扣）。季度调仓下 10% 档是合理近似。

### 6.4 两条纪律（这个项目用血换来的）

> ① **`N` 和 `hold` 都是噪声参数（±3~4pp），取保守值，别追样本外最高点。**
>
> ② **回测与实现不一致只能靠前向数据发现。** 本项目三次大坑 —— `hyst` 静默退化、引擎 `topk*2` 静默跳过、ETF 份额折算未复权 —— **全都是「回测与实现不一致」**。

## 八、可直接跑的代码（2026-09-17 新增）

本文的落地实现已写好，在 **`joinquant/`**：

| 文件 | 用途 |
|---|---|
| `joinquant/jq_dividend.py` | **主文件（唯一真源）**，整段贴进聚宽策略编辑器即可跑；顶部 `FORM` 切形态 |
| `joinquant/jq_dividend_naked.py` | **裸版对照**（只差配置行一行，由主文件生成），即 §6.1 建议必跑的对照 |
| `joinquant/_verify_core.py` | **离线自检**（不需要聚宽账号） |
| `joinquant/README.md` | 口径映射表、会分叉的 7 处、改动纪律 |

**离线自检的结论（2026-09-17 实跑）**：

1. **移植一致性 ✅** —— 5732 个 (股票, 除权日) 组合，聚宽路径的 `dy_ttm` / `n_div3`
   与本地 `build_yield_panel` **逐位一致**（不一致 0 个）→ 移植没引入口径漂移。
2. ⚠️ **查出本地 `dps_ttm` 的送转调整方向是反的** —— 判据是「送转价值中性 →
   纯送转除权日前后 `dy` 应连续」。实测中位比值：**现行口径 1.446**（精确贴合 `(1+r)`，即跳变）、
   修正口径 **1.008**（连续）。**修它会牵动全部历史结论，本次未改研究模型**；
   在聚宽上只需把 `jq_dividend.py` 的 `ADJ_MODE` 由 `'legacy'` 改成 `'correct'` 即可测修正口径。
   详见 `joinquant/README.md` §6.1。
3. ⚠️ 另发现：本地引擎 `cond_col` 是**等权买满**（选到 12 只就每只 1/12），
   文档 §2.5 那句「剩余资金留现金」与实现不一致 → 代码按实现走。见 `joinquant/README.md` §6.2。

> ⚠️ **新增的一处与本地分叉（务必知道）**：10 万 ÷ 20 = 5000 元/笔，
   而 A 股买入是 **100 股整手** → **股价 > 50 元的股票买不进 1 手，会被跳过**。
   本地引擎**不建模整手**。这是聚宽与本地最主要的结构性差异。
