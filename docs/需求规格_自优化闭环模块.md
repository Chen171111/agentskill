## 三、M1 · `tools/eval_candidate.py`（**最高优先**）

### 3.1 目标

输入一个候选因子 → 自动跑**五闸门** → 输出 `PASS / FAIL / REVIEW` + 证据表，并把 FAIL 记入已证伪清单。

### 3.2 CLI

```bash
$PY tools/eval_candidate.py \
    --factor-csv results/cand_dyfwd.csv \      # 或 --factor-col dy_fwd（面板已有列）
    --name dyfwd_event \
    --usage filter \                            # filter | score
    --threshold 0.06 \                          # usage=filter 时的阈值（因子值 ≥ 阈值才算候选）
    --weight 1.0 \                              # usage=score 时并入的权重
    --bars data/stockbars/bars_total_tax10.parquet \
    --adj-mode correct \
    --topn 20 --hold 60 \
    --neighbors topn=15,20,30 \                 # ② 邻域（默认这 3 点）
    --out results/eval_dyfwd_event.csv \
    --json results/eval_dyfwd_event.json
```

| 参数 | 必填 | 说明 |
|---|---|---|
| `--factor-col` 或 `--factor-csv` | **二选一** | `--factor-csv` 需含列 `date, code, <name>`（date 为 `YYYYMMDD` 字符串） |
| `--name` | ✅ | 用于产物命名与已证伪清单记录 |
| `--usage` | ✅ | `filter`（额外过滤） / `score`（与基线因子加权） |
| `--usage score` 时的基线 | — | 基线 = 定稿形态 `indpct` N=20 hold=60；候选 = 在**行业内 dy 百分位**上再乘/加候选因子分位 |
| `--adj-mode` | ✅ | `legacy`/`correct` |
| 其余 | 有默认 | 照上表；`--bars` 默认 `data/stockbars/bars_total_tax10.parquet` |

### 3.3 五闸门的**精确定义**（实现方不得改动判据）

| 闸门 | 判据 | 输出字段 |
|---|---|---|
| **① 样本内外同号** | `Δ = 年化%(候选) − 年化%(基线)`，在 **样本内 2019~2022** 与 **样本外 2023~2026** 上**同时 > 0** 且同号 | `gate1_pass`(bool) / `d_in` / `d_oos` |
| **② 邻域同向** | 在 `--neighbors` 给的 ≥3 个点上，**样本外 Δ 全部同号且 > 0** | `gate2_pass` / `d_neighbors`(list) |
| **③ 净成本后为正** | 用 **税后（tax10）+ 10 万真实年化%**（已含最低佣金 5 元惩罚）判定，即 `10万真实Δ > 0` | `gate3_pass` / `d_real10` |
| **④ 增量非冗余** | 与既有因子（8 因子 + `dy_ttm`）的 Spearman \|ρ\| **最大值 < 0.5**，**且**样本外 Δ > 0 | `gate4_pass` / `max_abs_rho` / `rho_top3` |
| **⑤ 机制可解释** | 自动化只输出**暴露差异表**（行业数 / 行业 HHI / `vol20` 暴露 / `illiq20` 暴露 / 平均持仓 / 换手 / 平均 dy）；判定规则：**存在至少一个维度差异显著（\|Δ\|>10% 相对变化）且方向与 Δ 同向** → `REVIEW`；否则 `FAIL` | `gate5_verdict`(`REVIEW`/`FAIL`) / `exposure_diff` |

**总判定**：`①∧②∧③∧④` 全 PASS 且 ⑤ = `REVIEW` → **`PASS`**（进影子期，需人工确认）；任一 FAIL → **`FAIL`**。

### 3.4 输出

| 文件 | 内容 |
|---|---|
| `results/eval_<name>.csv` | 一行：`name, usage, gate1..gate5, verdict, d_in, d_oos, d_real10, max_abs_rho, 备注` |
| `results/eval_<name>_detail.csv` | 逐区间 × 逐邻域明细：`区间, 构造, 邻域点, 年化%, 夏普, 回撤%, 年化换手, 10万真实%` |
| `results/eval_<name>.json` | 同上结构化 + `exposure_diff` |
| `state/refuted.jsonl` | **仅 FAIL 时追加**一行 `{"ts","name","usage","verdict","reason","evidence_file"}`（append，不覆盖） |
| stdout | 五闸门表格（`✓/✗`）+ 最终 verdict |

**退出码**：`0` = PASS 或 REVIEW；`1` = FAIL；`2` = 参数/数据错误。

### 3.5 实现步骤（建议顺序）

1. 载入面板：`prepare(ns)` 复用（约 1~2 分钟）→ **必须缓存**（见 §六-6）
2. 候选列并入面板：按 `(date, code)` left join；缺值处理**必须显式**（`--na-fill none|zero|median`，默认 `none` = 该样本剔除并**打印剔除比例**）
3. 基线计划：`plan_selections(mode="indpct", topn, hold, ...)`
4. 候选计划：`usage=filter` → 在合格池上加条件；`usage=score` → `score = indpct_rank + weight × candidate_rank`
5. 3 区间 × (基线 + 候选) 回测 → 记录 年化/夏普/回撤/换手/10万真实
6. 邻域：对 `--neighbors` 的每个点重复 5（**只跑样本外**，控制耗时）
7. 秩相关：候选列 vs 8 因子 + `dy_ttm`，逐日横截面 Spearman 后取**时间中位**
8. 暴露差异：对候选与基线组合，逐调仓日算 行业数 / HHI / `vol20` 暴露 / `illiq20` 暴露 / 持仓数 / 换手 / 平均 dy → 取中位
9. 判定 + 写盘 + 增量落盘（每完成一个区间 `flush_partial`）

### 3.6 验收

```bash
# 自检用例（必须能跑通且 verdict 可解释）
$PY tools/eval_candidate.py --factor-col dy_ttm --name selfcheck_dy --usage score --weight 1.0 \
    --adj-mode correct --out results/eval_selfcheck_dy.csv --json results/eval_selfcheck_dy.json
```
**期望**：因为是"把 dy 自己再加一遍"，闸门④ 必然 FAIL（\|\rho\|=1.0）→ 输出 `FAIL` 且 `state/refuted.jsonl` 追加一行。
**这同时验证了"评估器能否正确拒绝一个必然冗余的候选"。**

## 四、M2 · `tools/monitor_factors.py`

### 4.1 目标

每日/按需产出**策略健康指标**，越界即告警。**只读**，不写任何策略状态。

### 4.2 CLI

```bash

    --bars data/stockbars/bars_total_tax10.parquet \
    --adj-mode correct \
    --out results/monitor_20260918.csv \
    --strict                    # 越界返回 3；不加则只告警不失败
```

### 4.3 指标清单（**全部必出**）

| 组 | 指标 | 计算 |
|---|---|---|
| 信号 | 全区间 RankIC(60) / 样本外 RankIC | 逐日横截面 Spearman，取时间均值；t 值用 Newey-West 前先不做，**只报均值与 ICIR** |
| 信号 | ICIR = mean(IC)/std(IC) | 60 日滚动 |
| 信号 | **滚动 12 个月 IC** | 最近 250 交易日 |
| 信号 | **分年度 IC 为正的比例**（近 8 年） | 当前基准 **5/8** |
| 信号 | 十分位顶底差 + 单调性 | 复用 `test_dividend_factor` 的分档逻辑 |
| 组合 | 行业数 / 行业 HHI / 平均持仓 / 年单边换手 | 基准：HHI ≈ **0.050**、行业数 ≈ **20**、换手 2.64x |
| 组合 | `vol20` 暴露 / `illiq20` 暴露 / 市值分位（成交额代理） | 相对全池中位数 |
| 组合 | 平均 `dy_ttm` | 基准 4~6% |
| **前向** | 纸面跟踪名单的**实际前向收益** vs 回测样本外（7.45%）偏离 | 读 `state/paper_tracking/selection_*.csv` + 行情 |
| 拥挤 | 候选池大小 / 合格池 dy≥8% 的股票数（中位 21） | 复用 `diag_industry_hyst_overlap` 的池统计 |

### 4.4 阈值（写入 `config/monitor.json`，可调但**默认值不可改**）

  "ic_12m_min": 0.02,

### 4.5 输出与告警

| 项 | 内容 |
|---|---|
| `results/monitor_<YYYYMMDD>.csv` | 一行指标（**每日一文件，不覆盖历史**） |

## 五、M3 / M4

### 5.1 M3 · `tools/walk_forward.py`

```bash
$PY tools/walk_forward.py --bars data/stockbars/bars_total_tax10.parquet \
    --adj-mode correct --label-horizon 60 --embargo 60 --n-folds 5 \
    --min-train-days 500 --n-trials 28 --n-splits 16 \
    --out results/walkforward.csv --json results/walkforward.json
```

| 要求 | 说明 |
|---|---|
| **purged + embargo** | 训练段末尾剔除 `label_horizon` 天（purge），再额外剔除 `embargo` 天；测试段长度 = 剩余均分 `n_folds` |
| **输出** | 每折的 OOS RankIC / 年化 / 夏普 + 总体均值；**`DSR`（Deflated Sharpe Ratio）** 与 **`PBO`（CSCV，`n_splits=16`）** |
| DSR 公式 | Bailey & López de Prado：用 `n_trials` 校正多重检验；正态 CDF 用 `math.erf` 实现（**不可用 scipy**） |
| 验收 | 对现有 8 因子与 `dy_ttm` 跑一次，输出非空且 `PBO ∈ [0,1]`、`DSR` 为有限值；**不得报 NaN** |

### 5.2 M4 · `tools/daily_learn.py`

```bash
$PY tools/daily_learn.py --dry          # 打印计划，不执行
$PY tools/daily_learn.py                # 实跑
```

**四步（顺序固定，每步幂等）**：

| 步 | 动作 | 失败处理 |
|---|---|---|
| 1 | 个股线数据增量（调 `append_stock_bars`，只补最近几天） | 失败 → 写 `DATA_ALERT`，**继续** |
| 2 | 特征面板增量 + **缓存**（见 §六-6） | 失败 → 中止（后续都依赖它） |
| 3 | **标签回填**：把 `T − label_horizon` 之前的样本打上已实现收益 | 失败 → 中止 |
| 4 | 调 `tools/monitor_factors.py --strict` | 越界 → 保留 `LEARN_ALERT`，**退出码透传 3** |

**输出**：`state/learn/<YYYYMMDD>.json`（各步耗时、状态、指标摘要）+ `results/_daily_learn_<date>.log`

**红线**：本脚本 **只写 `state/learn/` 与 `state/LEARN_ALERT.txt`**，**不得**触碰 `state/trading.db`、`ALERT.txt`、任何策略参数文件。

## 十一、实现期发现的**规格缺口与处理**（2026-09-18 实施时补记）

> 规格要求"如存在不明确或缺失的部分，请指出并给出合理的默认处理方式"。以下 5 条是实施中真实撞到的。

| # | 规格原文 | 问题 | 处理（已实施） |
|---|---|---|---|
| **1** | §2.1「Spearman 用 `pandas.Series.corr('spearman')`」 | ❌ **不可行**。本环境 pandas 内部会 `from scipy.stats import spearmanr` → `ModuleNotFoundError: No module named 'scipy'`（venv 只有 pandas/numpy/pyarrow）。第一次跑 M1/M2/M3 **三个模块全崩** | 新增 **`tools/stats_lite.py`**：Spearman 用「**秩的 Pearson 相关**」自实现（定义上等价，并列值同样取平均秩），正态 CDF/分位数用 `math.erf` + 二分法。**M1/M2/M3 统一改用它**（单一来源）。已验：`nppf(0.975)=1.959964` ✓ |
| **2** | §八 交付物清单只有 4 个模块 + 配置 + selftest | 规格 §2.3 要求 M1/M2 都"构建面板"，§六-6 又要求缓存；而 §八 要求两模块**不互相 import** → **两难**：各写一份＝违反铁律 14；互相 import＝违反规格 | 新增 **`tools/panel_cache.py`**（`fingerprint()` + `build_panel()`），M1~M4 共用。这是**规格缺失的共享层** |
| **3** | §1.3「对既有引擎**只 import**，不修改」 | `plan_selections` 没有"注入候选"的入口。严格只 import 就必须在 `eval_candidate` 里**重写一遍选股逻辑** → 违反铁律 14（同一判据多处实现） | 给 `plan_selections` 加两个**可选**参数 `extra_ok` / `extra_score`，**默认 `None` → 既有行为逐位不变**（已断言）。理由：单一来源优先于"只 import"的字面约束 |
| **4** | §4.4 说"12 个键"，但只列了 **10 个** | 少 2 个键 → `selftest` 的"12 键齐全"检查无从写 | 补齐为 **12 个**：新增 `ic_all_min=0.03`、`decile_tb_min=1.0`（pp/年）。已写入 `config/monitor.json`，并在 `selftest` 里断言与 `monitor_factors.REQUIRED_KEYS` **逐一致** |
| **5** | M1 闸门⑤「PASS 必须人工确认」/ M3 的 `--n-trials` | 无法自动化定论；且"搜过多少个配置"只有人知道 | M1 ⑤ 只输出 `REVIEW`/`FAIL` 并把 PASS 权交人工（已实现）；M3 `--n-trials` 设为**必填语义**（默认 28）并在输出里打印提醒"**必须如实填写**，否则 DSR 无意义" |

**另一处必须记的实测事实**：`--ic-step`（M2）/ `--n-splits`（M3）这类性能旋钮
**会改变运行时长但不改变结论方向**，默认值已按"单次命令 ≤10 分钟"（规格 §六-10）设定；
若数据量增长导致超时，优先调这两个参数，**不要**拆散流程。
