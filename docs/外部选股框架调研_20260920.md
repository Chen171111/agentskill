## 三、为什么是 qlib（而不是星更多的 OpenBB / daily_stock_analysis）

主人要的是「量化**选股**」—— 即**因子 → 打分 → 组合**这条链路。三者定位完全不同：

| 项目 | 实际做什么 | 与需求的差距 |
|---|---|---|
| OpenBB (73k★) | 把各家数据聚合起来给你看 | **数据平台**，不含因子/选股/回测闭环 |
| daily_stock_analysis (65k★) | 抓行情+新闻 → LLM 写分析 → 推送 | **信息分析**，不产出可回测的因子/组合 |
| **qlib (48.7k★)** | **因子库 + ML 模型 + 回测 + 组合优化全链路** | ✅ **正好是这条链路** |

> 换句话说：星数高 ≠ 匹配。前两个是"**给你看**"，qlib 是"**算出来给你用**"。

## 四、接入成本与风险（**必须正视**）

### 4.1 ⚠️ 依赖重 —— 绝不能装进现有研究 venv

`pyqlib 0.9.7` 的核心依赖（实测 PyPI 元数据）：

```
pyyaml numpy pandas>=0.24 mlflow filelock redis dill fire ruamel.yaml
python-redis-lock tqdm pymongo loguru **lightgbm** gym **cvxpy**
joblib matplotlib jupyter nbconvert pyarrow pydantic-settings
```

**冲突点**：本项目研究 venv 的硬边界是「**只有 pandas/numpy/pyarrow**，
scipy/sklearn/lightgbm **均未安装且不建议新增**」（`HANDOFF §6.2`）。
而 qlib **把 `lightgbm` 列为必装**，`cvxpy` 还会间接带入 scipy。

→ **必须开独立环境**（单独 venv 或 conda），**不要动**
`C:\Users\XiaoQi\.workbuddy-ai\binaries\python\envs\default`。

### 4.2 数据格式不同

qlib 用自有 `.bin` 格式 + `~/.qlib/qlib_data/cn_data`，与现有
`data/stockbars/*.parquet` 不同 → 两条路：

- **省事**：直接下官方 `cn_data`（`python -m qlib.cli.data qlib_data --region cn`），
  与现有数据**并存**，互不干扰；
- **打通**：写一个 `parquet → qlib bin` 的转换，
  好处是能复用本项目**已经验证过的复权/分红口径**（`bars_total*`）——
  这点很重要：qlib 自带数据的复权口径是黑盒，而本项目吃过「复权口径」的大亏。

### 4.3 其它

- Python >= 3.8 ✅（本机 3.13/3.14 均可，但 qlib 对 3.13 的兼容性**未验证**，
  建议独立环境用 3.10~3.11）
- `mlflow` / `redis` / `pymongo` 是**实验管理/缓存**用，单机跑可以不启用
