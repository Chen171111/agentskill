# 同花顺交易窗口控件地图（网上股票交易系统5.0）

> 用途：`trader/ths_uia.py` 的自动化依据。本文件由 2026-09-11 实测得出，环境为
> 同花顺经典版 9.60.61 模拟炒股（`xiadan.exe`），Windows 10/11，32 位 Python。

## 0. 最关键的一条：同花顺有**两个**独立窗口

| 窗口标题 | 类名 | 性质 | 能否自动化 |
|---|---|---|---|
| `同花顺(9.60.61) - 自选股`（或其子窗口 `- ETFs分时走势`） | `Afx:00840000:...` | **行情**窗口，全屏 1934×1086 | ❌ 纯自绘，UIA 只能看到影子控件 |
| `网上股票交易系统5.0` | `Afx:00E50000:...` | **交易**窗口，约 1118×637 | ✅ 标准 MFC，控件句柄齐全 |

历史踩坑：早期实现按 `同花顺` 前缀匹配窗口，**抓到了行情窗口**，于是出现
「Edit 控件的 `BoundingRectangle` 不可信、`set_value` / `WM_SETTEXT` 全无效、
代码框一直空白」的假象。真正原因是从未操作过交易窗口。

**判定方法**：交易窗口标题固定为 `网上股票交易系统5.0`（前缀 `网上股票交易系统`）。
`trader/ths_uia.py::UiaThsBroker._find_trade_hwnd()` 按此定位。

## 1. 窗口结构

```
Window 网上股票交易系统5.0 (Afx:00E50000:...)
├─ ToolBar ToolbarWindow32            顶部工具栏（买入/卖出/撤单/查询/登录/退出…）
├─ Pane AfxMDIFrame140s (id 59648)    MDI 主区
│  ├─ Pane AfxMDIFrame140s (id 59649)
│  │  ├─ #32770  ← 当前**页面对话框**（买入页/卖出页/查询页都挂这里）
│  │  │  ├─ Static id=1478  页面标题：'买入股票' / '卖出股票' / '查询资金股票'
│  │  │  ├─ Edit   id=1032  证券代码
│  │  │  ├─ Static id=1036  证券名称（输入代码后自动带出）
│  │  │  ├─ Edit   id=1033  价格
│  │  │  ├─ Static id=1018  可买(股) / 可用余额
│  │  │  ├─ Edit   id=1034  数量
│  │  │  ├─ Button id=1006  买入 / 卖出（提交）
│  │  │  ├─ Button id=1007  重填（复位整张表单）
│  │  │  └─ CVirtualGridCtrl  下方表格（持仓/成交/委托）

│  └─ Pane AfxWnd140s                左侧菜单容器
│     └─ Tree SysTreeView32 (id 129) 左侧功能树
└─ 状态栏 Static                     时间 / 账号
```

## 2. 买卖页控件 ID（买入页与卖出页**完全共用**）

| 作用 | 控件 ID | 类 | 说明 |
|---|---|---|---|
| 页面标题 | 1478 | Static | `买入股票` / `卖出股票` / `查询资金股票` |
| 证券代码 | **1032** | Edit | 输入后客户端自动带出名称/参考价/可买量 |
| 证券名称 | 1036 | Static | 只读，自动带出（如 `红利ETF华泰柏瑞`） |
| 价格 | **1033** | Edit | 旁有 `msctls_updown32` 微调 |
| 可买(股)/可用余额 | 1018 | Static | 自动计算 |
| 数量 | **1034** | Edit | 旁有微调 |
| **提交按钮** | **1006** | Button | 买入页文本 `买入`，卖出页文本 `卖出` |
| 重填 | 1007 | Button | **复位整张表单**（唯一可靠的清空手段） |
| 可用比例 | 63360/63361/63363/63362 | Button | `1/2` `1/3` `1/4` `1/5` |

> 切页后控件 HWND 会变（页面对话框被重建），**必须重新按 ID 解析句柄**，不能缓存。

## 3. 顶栏资金 Static（可按 ID 直读，**不需要 OCR**）

| 字段 | 控件 ID |
|---|---|
| 资金余额 | 1012 |
| 冻结金额 | 1013 |
| 股票市值 | 1014 |
| 总资产 | 1015 |
| 可用金额 | **1016** |
| 可取金额 | 1017 |

同一 ID 可能存在多个实例（旧页面残留），取最后一个非空值即可。
校验恒等式：`总资产 ≈ 可用金额 + 股票市值`。

## 4. 左侧菜单树（SysTreeView32）

顶层：`买入[F1]` `卖出[F2]` `撤单[F3]` `自选股` `条件单` `双向委托` `市价委托`
`批量下单` `查询[F4]` `通用回购` `修改密码` `修改客户信息` `模拟大赛`

`查询[F4]` 下的子项：`资金股票` `当日委托` `当日成交` `历史成交` `历史委托`
`资金明细` `对账单`

## 5. 委托确认弹窗

- 是交易窗口的 **owned 顶层窗口**（`GetWindow(hwnd, GW_OWNER) == 交易窗口句柄`），
  **不是** `GW_CHILD` 子树的一部分 —— 用 `EnumChildWindows` 找不到，这是常见坑。
- 类名 `#32770`，标题为空，尺寸约 360×300。
- 按钮是标准 `Button`：
  - `是(&Y)` → 确认提交
  - `否(&N)` → 取消
  - `我的投资顾问提供了该投资建议` / `点击此处不再提示` → 广告位
- 弹窗正文由若干 `Static` 承载，主文案是**富文本**（含 `<font color=...>` 标签），
  需剥标签后解析：
  ```
  资金帐号：模拟炒股-UI**85
  证券代码：510880(红利ETF华泰柏瑞)
  买入价格：3.427 (卖一)
  买入数量：100
  预估金额：347.700
  您是否确定以上买入委托？
  ```
- 提交成功后另弹一个提示框：`您的委托已成功提交，合同编号：625377491。`（按钮 `确定`）

## 6. 输入框的怪脾气（决定实现方式）

1. **`WM_SETTEXT` 无效**：`SendMessage(WM_SETTEXT)`、`SetWindowTextW` 都**清不掉**内容。
   表现是内容被**追加**（连点两次 `100` 得到 `100100`）。证券代码框因为限长 6 位，
   看起来「正常」，容易掩盖这个 bug。
2. **`WM_GETTEXT` 不可信**：代码框能读回文本，价格/数量/可买框读回 `''` 或陈旧值，
   但界面显示是正确的。**不要用回读来判断填表是否成功**，以截图/下单弹窗为准。
3. **可用的填法**：
   - 清空：逐个投递**退格** `PostMessageW(hwnd, WM_CHAR, 8, 1)`
   - 输入：逐字符 `PostMessageW(hwnd, WM_CHAR, ord(ch), 1)`
4. **提交按钮**：`PostMessageW(hwnd, BM_CLICK, 0, 0)` 即可，**不需要窗口置顶、不需要焦点**。

## 7. 页面切换

- 顶层页（买入/卖出/撤单/查询）：向主窗口 `PostMessageW(WM_KEYDOWN/WM_KEYUP, VK_F1..F4)`
  走加速键，无需焦点。
- 查询子页（资金股票/当日委托…）：UIA 定位 `TreeItem` → `select()` + 真实鼠标点击中心点；
  点击前需先把窗口置顶（`SetWindowPos(HWND_TOPMOST)` → `HWND_NOTOPMOST`）。

## 8. 其他

- 数据表格是 `CVirtualGridCtrl`（自绘），UIA 无子项，只能用**精确到控件矩形的截图 + OCR**。
  不要整窗 OCR（顶栏金额会被截断误读，历史上出现过 `96.0`）。
- 同花顺以管理员权限运行时，Python 也必须同权限，否则消息被 UIPI 拦截。
  但**消息级方案对权限不敏感**（BM_CLICK/WM_CHAR 不需要前台焦点），
  只有「真实鼠标点击切页」那一步需要窗口可见且未被遮挡。
