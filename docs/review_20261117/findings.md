## F1 · P1 · 资金读取会优先取到隐藏页的旧值

位置：`trader/ths_uia.py:748`、`:760`、`:780`、`:782`。

`_read_static()` 返回顺序是“当前页 → 其他可见页 → 其他页”；`fetch_balance()` 的 `pick()` 却取 `vs[-1]`。存在同 ID、非空的隐藏页控件时，实际选中优先级最低的值。

复现 `probe_hidden_balance`：当前页现金为 100、隐藏页为 999，候选列表是 `[100, 999]`，最终读出的现金为 **999**。这些数字都是合成样本。

影响：隐藏页市值与当前持仓不一致时，对账可能拒绝；市值恰好自洽而可用资金陈旧时，错误现金仍会流入购买力与总资产计算。已有自检检查了页面过滤的代码片段，未检查这一最终选择行为。

修复方向：明确按优先级取首个可信值；分别覆盖当前页、多个可见页、仅隐藏页、空值四类读取行为。

## F2 · P1 · 合法空仓被下单前对账拒绝

位置：`trader/ths_uia.py:1371`；对照该文件 `:1037`。

`reconcile()` 把 `market_value <= 0` 直接判为资金读取异常。合法全现金账户的持仓市值就是 0；后面的 `_pos_ok()` 原本能够接受“空持仓、零市值、现金有效”，但该路径到不了。

复现 `probe_empty_account`：现金有效、持仓市值 0，返回 **False**，连持仓读取函数都没有调用。

影响：首次空仓启动，以及趋势过滤/熔断清仓后的重新入场，可能一直失败。下单后的正常全清仓也会被误判为对账失败。

修复方向：区分“字段缺失/非有限值/负数”和“已确认的零持仓”；现金与总资产、空持仓明细共同校验，不能简单删除全部保护。

## F3 · P1 · 实际持仓峰值不随上涨更新，回撤止盈漏触发

位置：`trader/ths_uia.py:1398`、`:1410`；`account/portfolio.py:93`；对照 `backtest/account.py:67`。

真实券商对账保存的峰值只有 `max(cost, old_peak)`，没有纳入当前价；账户快照也不更新峰值。回测账户则每天用价格更新峰值，因此两条路径的回撤止盈不同。

复现 `probe_peak`：合成成本 100、原峰值 100、观察到现价 120，对账后峰值仍为 **100**；随后价格 101，实际路径不触发止盈。把峰值正确设为 120 的对照会触发 15% 回撤止盈。

修复方向：可信行情/持仓估值更新持仓峰值，并明确重建持仓、加仓、清仓再入场时峰值生命周期；与回测共享这一状态更新规则。

## F4 · P1 · 默认 ETF 回测缺少每日交易已有的绝对动量过滤

位置：`scheduler/runner.py:385`—`:405`；对照 `backtest/engine.py:205`—`:229`。

每日交易在策略选出标的后，额外要求“四舍五入到两位百分数后的 20 日动量 > 0”；回测只做策略、仓位上限、择时和组合风控，没有这一过滤。站上 MA60 并不保证 20 日动量为正。

复现 `probe_signal_divergence`：同类合成行情下，标的仍站上 MA60，但 20 日动量 **−3.2%**。每日交易剔除、最终空仓；回测仍持有该 ETF。

用现有缓存复跑 README 命令，并在保持数据、费用、次日开盘撮合等条件不变时，仅加入该过滤：

| 口径 | 累计收益 | 年化收益 | 最大回撤 | 夏普 |
|---|---:|---:|---:|---:|
| 当前 README 回测 | 28.2755% | 3.3133% | −9.3525% | 0.4737 |
| 同一回测，仅加入交易路径的动量过滤 | 34.9263% | 3.9992% | −8.1866% | 0.6121 |

两组区间均为实际面板的 **20190102—20260911**、ETF全球 11 只、TopK=5、5 日调仓。累计收益差 **6.6508 个百分点**。第二组只是单项差异的对照，**不能当作已经复原实际交易的回测**：执行时点、持仓更新和其他缺陷仍有差异；这里也没有提出替换策略的收益建议。

修复方向：策略资格过滤形成共享函数，两条入口调用同一逻辑；保留配对回归，明确舍入和阈值语义。

## F5 · P1 · 全部拒单或交易后对账失败，仍报告成功并推进调仓计数

位置：`trader/execution.py:79`—`:93`；`scheduler/runner.py:437`、`:500`、`:512`；`tools/daily_job.py:298`—`:330`。

执行器会保留拒单/异常订单，但运行器不据此判失败，最终仍返回 `status="ok"`。交易后对账失败也只打印警告、跳过净值，却仍推进计数并返回成功。每日任务仅以子进程退出码判断成功，正常返回会走清告警分支。

两个独立复现：

- `probe_rejected_success`：订单全部 `rejected`，结果仍为 **ok**，计数从 0 推到 **1**。
- `probe_post_reconcile_success`：下单前对账通过、下单后返回 False；净值未写入，但结果仍为 **ok**，计数同样推进。

影响：实际未达到目标组合，监控却显示成功，下次正常调仓还可能被推迟。不能把“委托已提交”和“目标完成”混为同一个状态。

修复方向：区分已提交、部分完成、全部拒绝、成交未知、账本未确认；向每日任务传递结构化状态和适当退出码，同时保留所有已知委托事实。

## F6 · P1 · 回测区间内部的未来折算仍可改变更早的多因子选股

位置：`dataprovider/store.py:278`—`:290`；`dataprovider/adjust.py:228`—`:231`；`factors/registry.py:17`—`:22`；`pipeline.py:38`—`:43`。

已有修复只是在“整次回测截止日”裁剪后复权。回测区间内、决策日之后发生的折算，仍会缩放决策日之前的整段价格；MACD 柱按绝对价差计算，参与跨标的排名时会随这一缩放改变。

复现 `probe_within_window_lookahead`：两份完全相同的历史前缀，观察同一个合成决策日。仅将数据末尾延长到后来的一次 1:2 折算以后，使用合法的 `MultiFactorStrategy(specs=[("macd_hist",1,1)])`，历史第一名从 **510300.SH 改为 510500.SH**。原始输出保存了两个因子值与选股结果。

影响范围：已经证实的是绝对价格 MACD 的横截面多因子排名，不能据此宣称默认 ETF 百分比动量也存在同样的排名变化。绝对历史价格与整手、最低佣金的组合也需要独立处理。

修复方向：把点时可知信号、公司行为、可成交原价分开；跨标的 MACD 可考虑价格归一化，并以“延长数据后，较早决策是否改变”的前缀一致性测试验收。

## F7 · P1 · “立即落订单”实际在整批提交之后，中断仍会丢失已报单记录

位置：`trader/execution.py:77`—`:94`；`scheduler/runner.py:414`、`:422`。

`rebalance()` 提交完整批次后才返回，运行器随后保存订单。第一笔报出、后续提交仍在进行时，数据库里还没有第一笔记录。

复现 `probe_batch_persistence`：模拟券商第一笔返回 submitted，第二笔注入 `KeyboardInterrupt` 模拟进程中断；临时数据库中订单数为 **0**，模拟券商已记录 **1** 笔提交。没有杀死真实交易进程，也没有操作真实委托。

影响：进程退出或被终止后，已提交委托缺少本地记录；恢复流程难以确定哪些订单已报，重入时有重复提交风险。

修复方向：逐笔提交前持久化订单意图，提交后立即更新状态和券商编号；恢复时先查询未决订单，再决定重试。仅在批次返回后落库不足以覆盖这一窗口。

## F8 · P1 · 交易入口接受大盘择时参数，却没有执行

位置：`scheduler/runner.py:63`、`:403`；`main.py:302`、`:316`、`:325`；对照 `backtest/engine.py:57`—`:69`。

`DailyRunner` 保存 `self.timing`，随后整个 `run_once()` 都没有读取它。CLI 的 `run/simulate/daemon --timing` 看似有效，实际上没有仓位效果；回测会执行这一参数。

复现 `probe_timing_ignored`：传 `timing="bias"`，合成行情在回测的择时仓位系数为 **0**，每日交易最终仍给出 **30%** ETF 权重。

修复方向：接入共享择时计算和一致的基准、预热区间；实现前应明确拒绝交易入口不支持的选项，避免静默忽略。

## F9 · P2 · 未成交卖单被提前计入买入购买力

位置：`trader/execution.py:49`、`:57`、`:75`。

买卖订单在提交前一次性生成，`cash_left = account.cash + sell_proceeds`；卖单尚未成交甚至尚未提交，其预计回款已经用于买单预算。先提交卖单不保证卖单已成交。

复现 `probe_sale_budget`：可用现金 **0**、卖单仍为 submitted，执行器仍报出名义金额 **3000** 的买单（均为合成数据）。

影响：真实券商通常会拒绝资金不足的买单，导致换仓不完整；这里未证明券商会允许透支，不应将它描述成一定造成超买。

修复方向：卖出后按实际成交/可用现金重新计算买单，对未成交与部分成交保留明确状态；费用缓冲应来自真实成本函数。

## F10 · P2 · Windows 自检对子进程中文输出的编码约定不完整

位置：`tools/test_quant_desktop.py:99`—`:108`；`tools/desktop_stock_smoke.py:40`。

父测试用 UTF-8 解码子进程输出，子进程却没有显式指定 UTF-8；在本机默认编码环境中，中文指标名变成替换字符，`年化收益` 键断言失败。父解释器的 `-X utf8` 不会自动作为参数传给子解释器。

对照：仅给子进程环境增加 `PYTHONUTF8=1`，自检从 **38/39 变为 39/39**；两份完整输出均保存。这是编码/测试可移植性问题，本次没有把它认定为收益计算错误。

修复方向：子进程显式设置 UTF-8，或 JSON 使用 ASCII 转义；测试在有/无 UTF-8 环境变量两种条件下都应通过。
