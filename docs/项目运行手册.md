## 四、可能出现的报错与处理

### 4.1 数据层

| 报错 / 现象 | 原因 | 处理 |
|---|---|---|
| `[refresh] 需下载 XXX 但缺少 akshare(...)` 且退出码 0 | 该解释器**确实**没有 akshare → 静默失败 | ⚠️ **先别急着换数据源**：确认用的是 `E://Python//python.exe`（3.14，用户 site-packages 里有 akshare 1.18.94）。若在沙箱/自定义环境里跑，`sys.path` 可能被改过 → 用 `PYTHONPATH=<用户站点目录>` 补上。**真实计划任务里这条不会出现** |
| `行情数据陈旧：最新 X，应为 Y。…拒绝在陈旧数据上下单。` | 陈旧度守卫触发 | 这是**保护**，不是 bug。先刷新数据再跑 |
| `[refresh] 未知的池名：'XXX'` | 池名拼错 | 用 `config.RECOMMENDED_POOLS` 里的名字（默认 `ETF全球`） |
| `ModuleNotFoundError: No module named 'pandas'` | 用错解释器（32 位环境没装 pandas） | 回测/研究一律用托管 venv |
| 中文乱码 / `UnicodeEncodeError` | Windows 控制台默认 GBK | `set PYTHONIOENCODING=utf-8`（`daily_run.bat` 里已设） |

### 4.1b ⚠️ 份额折算：**读取时自动复权**（2026-09-16 根治）

**背景**：ETF 份额折算会让价格跳变（如 510500 在 2015-04-15 从 2.243 → 7.818，+248.6%），
但真实收益是连续的。`data/stocks/*.csv` 是 akshare 的**不复权**数据。

**09-13 修好的 4 处，09-16 被每日刷新静默回退了** ——
`refresh()` 会用 akshare 的**原始未复权全量历史**覆盖 CSV。代价 **0.98pp/年**。

**现在的机制（两道防线）**：

| 防线 | 位置 | 行为 |
|---|---|---|
| ① **读取时自动复权**（根治） | `dataprovider/adjust.py` → `DataStore.read()` | 无论文件被覆盖多少次，策略读到的永远连续；**幂等**；写 `state/split_repairs.log` 留痕 |
| ② **刷新后体检** | `tools/refresh_data.py` | 复权后**仍有**超阈跳变 → 写 `state/DATA_ALERT.txt` + **退出码 3** |

⚠️ **判据阈值是 0.35，不是 0.20**（2026-09-16 晚修正）：
**A 股 ETF 的涨跌幅限制按板块分** —— 沪深主板 **10%**、创业板/科创板 **20%**、
北交所 **30%**（制度预留，尚无品种）、跨境 ETF **10%**、商品/黄金 ETF **10%**、债券/货币 ETF **10%**。
> ⚠️ 早前写的「部分跨境 / 商品类 ETF **可能无涨跌幅限制**」**是错的**（已按交易所官方文件更正）。
> 制度依据与三个误传澄清统一收在 **`docs/参考_A股ETF涨跌幅限制.md`**，此处不重复。
所以 `> 20%` 的判据会与涨停带重叠：
`159949.SZ` 2024-10-08 的 **+20.02% 真实涨停**曾被误判成折算、抹掉当天收益（已确证是涨停：
成交额 141.87 亿创上市新高、份额折算比例字段 `--`、无折算公告）；
`159915.SZ`（**在实盘池内**）2024-09-30 恰好 +20.00%，只因浮点舍入
（`0.19999999999999996 < 0.20`）才侥幸逃过。
对照实验（`tools/probe_split_thresh.py`）显示误判代价 **−0.67pp/年**、夏普 −0.08。

**取 0.35 的依据**：必须高于**现行**最高涨停带（双创 20%，实测最高 +20.02%）
**并预留北交所 30% 档**（北证50 ETF 上市后 0.25 就会失效），
又要低于最小真实折算（池内 4 处实测，最小 **49.18%**）——
全库 ETF 扫描（`tools/scan_return_bands.py`）显示 **21%~40% 完全空白**，0.35 落在其中：
距 30% 预留档 **5pp**、距 49.18% 最小折算 **14.2pp**。

**判据的四处实现已统一**（原为 0.20 / 0.25 / 0.20 / 0.20 各不相同）：
`dataprovider/adjust.py`（单一来源）、`tools/diag_price_anomalies.py`、
`tools/repair_etf_adjust.py`、`tools/sweep_etf_pool_expand.py`。

⚠️ **已知边界**：① 真实折算幅度若落在 **21%~40%** 会被漏检（当前全库无此案例）；
② 结论基于 `data/stocks` 的 **27 只 ETF 样本**，非全市场，扩池后应重跑扫描。
根治方向是**二次判据**（精确份额比 / 净值交叉验证 / 折算公告白名单），不是继续调阈值。
详见 `docs/参考_A股ETF涨跌幅限制.md` §六、`tools/README.md` 铁律 14、

### 4.3 研究 / 回测层

| 报错 | 原因 | 处理 |
|---|---|---|
| `ValueError: 区间过短: N 天` | 区间 < `hold × 4` | 缩短 `--hold` 或拉长 `--start/--end` |
| 内存不足 / 进程被杀 | `bars_total*.parquet` 约 400MB，多进程并行会叠加 | **一次只跑一个大任务**；长任务加 `run_in_background` |
| 曲线出现"断崖" | 先怀疑引擎静默守卫，别当成 alpha 衰减 | 见 `tools/README.md` 铁律 5 |
| 参数改了但结果没变 | **参数没生效**（静默退化） | 见铁律 8：判据是"结果与基线不同"，不是"平均持仓 < N" |
| 打印进度看不到 | `print` 重定向到文件时默认带缓冲 | 长任务一律加 `flush=True`（或 `python -u`） |
| 电脑死机（有先例） | 大批量任务把成果压在内存里 | **增量落盘 + 断点续跑**，别攒到最后一次写 |

## 六、定时任务与无人值守

`daily_run.bat` 的流程（**两步必须分两个解释器**）：

```
Step 1/2  E:\Python\python.exe   tools\refresh_data.py     # 64 位刷行情

```

`daily_job.py` 在 `main.py` 外面包了一层，负责：

- 把结果写成结构化状态 `state/last_run.json`
- **失败时写显眼的 `state/ALERT.txt`**（含原因 + 日志尾部），成功时自动清除
- 用**非零退出码**向上传递 → Task Scheduler 的 `LastTaskResult` 能看到

**排障顺序**：`state/ALERT.txt` → `state/last_run.json` → `state/daily_run.log` 尾部。
或者直接跑 `$PY tools/check_alerts.py`。

安装/重装定时任务：`install_schedule.bat`。
